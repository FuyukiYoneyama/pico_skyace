作成日: 2026-09-09 / 基準: v0.9.0（`4c599e6`） / 実装対象: v1.0.0

完全経路検証追記: 2026-09-10。製品BIN（短縮マクロなし）でTitle→Demo→Titleの
30秒／30秒期限を公式LCDエミュレーターで、Play→GameOver→Titleの10秒期限を
UART専用高速PIOシンクで完走させ、UARTの`time_us`とrunner reportを保存した。
追加の厳密33秒UARTガード、直接リトライ、ポーズ復帰、武器・標的境界、SDあり／なし、
音声操作入力、公式LCD framebufferの短時間シナリオも合格し、証跡を
[`build-artifacts/2026-09-10-nonhardware/`](../build-artifacts/2026-09-10-nonhardware/)へ保存した。
2分の代表上限負荷も例外・入力dropなしで完走した。さらにユーザー報告により、
20分間の上限負荷プレイも問題なく完了したため、長時間安定性の手動受入を記録する。
ただし、GameOverの公式LCDを含む長時間framebuffer版、実機フレーム時間p95、
メモリ／実行時スタック余裕はなお未計測であり、[ビルド記録](validation/2026-09-10-demo/BUILD.md)と
[リリースチェックリスト](RELEASE_CHECKLIST.md)ではそれらを別の未確認項目として維持する。
なお、実機不要の診断BINで300フレームの処理時間p95とスタック高水位を取得したが、
高速PIOシンク上の仮想値であり、33msの実機合否には採用しない。

難易度調整追記: 2026-09-10。実機プレイで「Waveが進んでも敵数以外の圧力が
変わらない」とのフィードバックを受け、`game_rules::EnemyWaveTuning`を追加した。
Wave 1を基準に、後半Waveほど敵の追跡開始距離・攻撃選択率・旋回速度・移動速度・
射撃距離・射線幅・高度許容・命中率を段階的に強め、射撃クールダウンを短縮する。
攻撃前の18フレーム警告は維持し、敵数の上限5と固定配列は変更しない。後半Waveで
攻撃が増えることはホストテストで確認した。実機プレイで「非常によくなった」との
受入報告を受けたため、Wave攻撃性調整は完了扱いとする。1.0.0最終UF2では同じ
挙動を再確認する。`VERSION`の1.0.0更新と最終ビルドは従来どおり保留する。

攻撃方向表示追記: 2026-09-10。`INCOMING`警告中に攻撃元を視野中心基準で判定し、

照準周囲には同じ方向を指す赤い矢印を常時表示し、画面内の攻撃機にも方向手掛かりを

敵攻撃警告音追記: 2026-09-11。敵が攻撃態勢へコミットした時（現在は出現時から
追尾）またはWaveごとの攻撃距離へ初めて入った時に低い接近警告を1回、射撃距離・
正面角・高度差が成立して18フレームの発射予告を開始する時に高く荒い交互音の
発射準備警告を1回鳴らす。接近警告は境界付近の連打を避けるヒステリシスを持ち、
低く重い交互音とする。
発射準備警告は射線が外れて予告が取り消された場合に再度鳴る。接近警告は断続する
電子ブザー、発射準備警告はピーと続く連続高音のロック警告とし、ザーというノイズ
だけの音を避ける。
SFXには優先度を設け、
連射音で警告・被弾音が消えないようにした。デモ中の効果音抑制とタイトル曲の連続再生は
維持する。音量・識別性の最終確認は実機スピーカーで行う。

戦闘継続性・弾数・Wave演出追記: 2026-09-12。敵機は出現時から自機を追尾し、攻撃
態勢を維持する。攻撃態勢では最低速度を設け、直進放置の自機にも射撃機会が発生する
ようにした。GUNにWaveの敵機数×30発の残弾を持たせ、命中範囲を従来より広げた。
GUNとミサイルが同時に尽きた場合は`OUT OF AMMO`でゲームオーバーとし、最後の敵を
倒したフレームはWaveクリアを優先して次Waveの補給へ進める。全滅後は45フレームの
全画面を明るい青〜シアンで静止させた`WAVE CLEAR`演出と短い上昇ファンファーレを
表示・再生し、右上の`WAVE`下に残敵数を表示する。

敵AI初動・デモ開始・背景色追記: 2026-09-12。Wave開始直後は旧来どおり敵を遠巻きの
巡航状態に置き、残敵が開始時の半分以下、またはそのWaveの経過が20秒を超えた時点で
全生存機を攻撃フェーズへ移す。遠巻きフェーズでは攻撃モードへの乱数遷移と接近警告を
抑制し、近づきすぎた機体は自機から離れる。デモは`reset_game(4)`でWAVE 4から開始し、
デモ中の死亡後もWAVE 4から再出撃する。背景の太陽は白色中心から暖色系の黄色へ変更した。

性能ログ準備追記: 2026-09-12。実機でデモを5分放置するだけで集計できるよう、
`PICO_SKYACE_PERF_DIAGNOSTICS=ON`の診断ビルドを追加した。最初の`Title->Demo`で
初期化完了時に`PERF_DEMO event=boot`、最初の`Title->Demo`で
`PERF_DEMO event=start`を1回、Demoの境界ごとに`session_start`／`session_end`、
5分窓の完了時に`PERF_DEMO event=done`を1回だけ出力し、
行内を空白区切りの`key=value`（`schema=1`）で統一する。p95はDemo描画完了フレームのみ、
Title帰還は`non_demo_frames`、デモ中の死亡再出撃は`demo_resets`へ分離する。完了行には
フレーム時間（min/avg/p95上限/max）、33ms目標判定、スタック高水位・空き・オーバーフローを
含める。製品ビルドの既定値は診断OFFで、性能ログの値を実機以外の合否証跡には採用しない。
手順とフィールド定義は[`docs/PERF_DIAGNOSTICS.md`](PERF_DIAGNOSTICS.md)に固定した。

実機性能ログ追記: 2026-09-12。ユーザー提供の`20260912_125652.log`で、最初のDemo開始から
300.028秒の計測窓を完走した。Demo 2,480フレームのp95上限は64.999ms、平均60.391ms、
最大64.566ms、スタック使用1,200/4,096バイト（空き2,896、オーバーフローなし）だった。
31.25MHzで320x320 RGB565全画面を送るデータ量だけで約52.4msを要するため、計画上の33msは
現行の安定設定では実現困難な暫定目標と判断し、v1.0の機能リリースゲートから外して実測
ベースラインとして記録する。30fps化はLCD高速化・部分転送を含む別の将来検討とし、今回の
リリースでは表示安定性を優先する。ログ冒頭の`WATCHDOG_CAUSED_REBOOT=1`は計測前の起動を
示すため、最終ビルド前に完全電源OFF/ONで`=0`を一度確認する。
この挙動変更に合わせて`VERSION`を0.9.4へ更新する。

実機性能ログ版更新追記: 2026-09-12。診断ログの境界記録追加に伴い、PicoCalc向けソースの
版番号を`0.9.15`へ更新した。`20260912_135758.log`は`version=0.9.15`の起動を1回記録し、
`watchdog_reboot=0`、最初のDemoから300.011秒後の`event=done`まで完走した。Demo 2,480
フレームのp95上限は64.999ms、平均60.409ms、最大64.621ms、スタック使用1,208/4,096
バイト（空き2,888、オーバーフローなし）、`demo_resets=0`である。完了後に追加の起動境界が

1行でも変更したら、内部診断を含めて`VERSION`を必ず上げ、同じ版番号のUF2を配布しない。

## 1. 目指す体験

**「小さな画面でも敵を追えて、撃墜が気持ちよく、もう一度出撃したくなる空戦ゲーム」**を目指す。

後方追従の疑似3D、固定小数点、PicoCalcのキー操作という現在の特徴を活かす。最初は操作と戦闘のわかりやすさを磨き、次に短いミッションと戦績を加える。完成形の目安は、1回3〜5分程度のミッションを遊べる構成。既存のウェーブ制はエンドレスとして残す。

## 3. 実装の順序

### Phase 0: 比較基準と挙動を固める

目的は、改善前後を比較できる状態にすること。

- 現行版で開始、旋回、ロック、機銃、ミサイル、Wave移行、墜落、再出撃を確認し、UARTログとF5画像を保存する。
- 更新・描画・LCD転送の時間を分けて計測し、通常戦闘と上限負荷で中央値・95パーセンタイル・最大値を記録する。RAM/Flash使用量もビルド成果物から記録する。
- デバッグ用の固定乱数シードと入力手順を用意する。描画の機銃トレーサは`fm::rnd_fx()`を使うため、演出用乱数を戦闘用と分けて比較の再現性を確保する。
- 次のコード上の懸念を再現確認し、影響のあるものを先に修正する。

| 確認対象 | 根拠と確認方法 |
|---|---|
| 開始直後に初期状態が変わる | 開始したフレームからPlayを描画し、`reset_game()`後に`render_title()`を呼ばない。最初の移動前に高度800m、yaw/pitch/roll=0、速度90m/s、HP100、Wave 1、ミサイル12発（初期8＋Wave補給4）であることを検証する |
| 照準判定が前回描画の情報を使う | 前フレームの描画キャッシュ依存を解消する。移動→カメラ・投影更新→武器判定→結果判定→描画の順を定義し、当該フレームの判定とHUDで同じ投影を使う。ロール係数も現在の`render_background()`から計算処理を分離する |
| 残存ミサイルが次Waveの別機体を追う | 標的を敵スロット＋生成番号で識別する。誘導と`missile_targets()`の回避判定の両方で一致を確認し、標的消失後は無誘導で寿命まで飛行する。新しい敵を自動再捕捉しない。近接命中は引き続き別の敵にも成立する |
| ゲームオーバー後に戦績が変わる | 終了時に結果を1回だけ保存し、GameOverでは敵・武器・ダメージ・加点を更新しない。爆発減衰とUI点滅のみ継続できる。結果画面と背面HUDも確定値を使う |

#### Phase 0の再現・計測手順

- 基準ソースは`4c599e6`。SDKの実在パスとリビジョン、ARM GCC/CMake/Ninjaのバージョン、ビルド設定、ソース差分、UF2のSHA-256を記録する。既存`build/`の成果物は上書きせず、`mktemp -d`で作る専用の`/tmp`作業ディレクトリで基準版をビルドする。
- 基準版の実機記録を取った後、計測だけを追加した版と挙動修正版を区別する。乱数分離や更新順変更も挙動変更として記録し、無改変基準版との完全な戦闘一致は要求しない。
- `fixmath`に`seed_rng(uint32_t)`を追加し、ゼロは既定の非ゼロ値へ置換する。テストでは出撃の初期化直前に毎回同じシードを設定する。演出は別の乱数状態を持ち、タイトル滞在時間や描画回数でテスト中の戦闘乱数が変わらないようにする。
- 再現入力は`tick,key,state`（stateはPressed/Hold/Released）で保存し、Play開始をtick 0とする。ホストではI2Cの代わりに同じ入力処理へ注入する。実機の手動操作記録は体験確認に使い、フレーム単位の再現証拠とは区別する。
- 性能は通常戦闘と敵5・ミサイル4・爆発6の負荷シナリオを各3回、各1800フレーム測る。上限維持のテスト用生成処理は計測区間外に置き、戦闘AI・描画・音声処理は含める。
- `time_us_64()`等で入力処理、更新、描画、LCD転送、待機を除く合計時間を計測する。毎フレームのUART出力は避け、固定容量の集計を使い計測後に出力する。集計方式・分解能と計測による負荷を記録する。F5と画面遷移は通常戦闘集計から分ける。
- ログは`scenario,run,frames,metric,unit,median,p95,max`を基本形式とし、UARTログ、入力CSV、F5画像、サイズ情報、実行条件を`docs/validation/<日付>-phase0/`へ保存する。バイナリ本体の保管先とSHA-256を同じ記録から追えるようにする。
- UF2/ELFはGit管理対象に追加せず、比較用の基準版・計測版・修正版をプロジェクト内の`build-artifacts/<日付>-phase0/<版>/`へ保管する。この場所は既存の`build*/`除外規則に従う。Git管理する検証記録には相対保管先、サイズ、SHA-256、ソースリビジョンと差分、再ビルド手順を残す。コピー後にハッシュ一致を確認し、検証完了まで保持する。ローカル保存はバックアップや公開配布を保証しないため、配布時は別途配布先とハッシュを記録する。`/tmp`だけを正式な保管先にしない。

#### 終了判定と結果データ

- 出撃ごとにプレイ用tickを0へ戻す。飛行時間はPlayで実行した更新回数÷30のゲーム内時間（秒未満切り捨て）とし、タイトル、ポーズ、F5保存、GameOverの待ち時間を含めない。描画用`g_frame`とは別に管理する。
- `DeathReason`はNone / ShotDown / Crash / Collision / OutOfAmmo。HPを初めて0以下にしたイベントで敗因を固定する。弾切れは敵が残っている状態でGUNとミサイルが同時に0になった時に確定する。敵との体当たりは敵を撃墜扱いにせず、自機へダメージを与えた上で敵を離脱させる。墜落を最初に判定し、同じ敵からの射撃と衝突が同tickに成立する場合は射撃を先に処理する。複数敵はスロット順とする。
- 死亡確定後、そのtickの残りの戦闘処理を停止する。死亡前に成立した加点は保持し、死亡後の撃墜・Wave補給は実行しない。これは現行の更新順からの意図的な変更で、同時イベントのテストで固定する。
- 停止判定はフレーム末尾だけに置かない。墜落判定直後、各敵の射撃ダメージ直後、各衝突イベント完了直後に死亡を確認し、呼び出し元まで終了を伝播させる。致死射撃後に同じ敵の衝突処理を行わず、致死衝突はダメージを確定してから停止する。後続敵・ミサイル・Wave移行へ進まないことを個別テストで検証する。
- 結果にはスコア、到達Wave、撃墜数、プレイtick、敗因を保存する。撃墜数は機銃・ミサイルで敵がaliveからdeadへ変わった時に1回だけ加算する。敵との衝突は撃墜数・撃墜スコアに含めない。

完了条件: 上記4件の修正と再現テストが合格し、基準版・修正版のビルド記録と実機比較、性能基準が揃う。実機を利用できない場合もホストテストとビルドは進められるが、Phase 0の実機検証完了とは扱わず、Phase 1の正式着手判定を保留する。

### Phase 1: 操作と戦闘の手応えを改善する（最初の公開範囲）

1. **再挑戦とポーズ**: 下表の状態遷移と入力抑制を実装する。ポーズ中は戦闘タイマー・HP・弾数・プレイtickを進めない。ゲームオーバーは10秒でTitleへ戻し、Titleはタイトル曲を継続したまま30秒でDemoへ遷移する。Demoは同じ曲を流しながら自動攻撃を行い、30秒でTitleへ戻す。
2. **敵を追いやすくする**: 最初のWaveは前方の見つけやすい位置に出現。画面外には選択中の目標1機の方向矢印を表示し、複数の案内で画面を埋めない。真後ろ・上下方向・画面端での挙動を定義する。
3. **ロックと命中を伝える**: 20フレームの進行ゲージ、短い機銃ヒットマーク、弾切れ／同時ミサイル上限で発射できない場合の短い表示を加える。ロック枠から外れた瞬間のリセットが厳しければ、短い猶予を試す。
4. **被弾を理解しやすくする**: 射撃前の画面警告と方向表示を導入し、旋回で射線を外す意味を明確にする。敵が攻撃態勢へ入った時は断続する低い電子ブザー、射撃距離・方向・高度条件が成立した時はピーと続く連続高音のロック警告を鳴らす。警告と被弾音は機銃連射より高い優先度で再生する。初期案は予告0.5〜0.8秒。予告後にも射程・方向・高度条件を再判定し、回避できた場合はダメージを与えない。
5. **結果を読みやすくする**: スコア、到達Wave、撃墜数、飛行時間、敗因（撃墜／墜落／衝突）を確定表示する。狭い画面に収まる短い英語ラベルを使う。

主な変更先: `src/game/game.cpp`、必要に応じて`src/platform/picocalc_audio.*`、操作説明の`README.md`。

| 状態 | キー | 遷移・動作 |
|---|---|---|
| Title | Enter | 初期化してPlayへ |
| Play | P または Esc | Pauseへ。エンジン音を停止する |
| Pause | P または Enter | Playへ復帰 |
| Pause | Esc | Titleへ。再押下が必要 |
| GameOver | Enter | 結果と出撃状態を初期化して直接Playへ |
| GameOver | Esc | Titleへ |
| GameOver | 入力なし（10秒） | Titleへ自動帰還 |
| Demo | Enter | 初期化してPlayへ |
| Demo | Esc | Titleへ。タイトル曲を先頭から再生 |
| Demo | 入力なし（30秒） | Titleへ自動帰還 |
| 全状態 | F5 | 表示中の画面を保存し、状態は維持 |

Pauseには`P/ENTER: RESUME`と`ESC: TITLE`を表示する。同じフレームのイベントで2回遷移しない。Pause・再出撃からPlayへ入る際は、そのフレームの操作を消費し、保持中の操作キーをReleasedまで無効化する。単に`down`を消すだけでは次のHoldで復活するため、キーごとの解除待ちを持つ。以後の新しい押下で操縦・射撃を再開し、エンジン音は復帰後の速度から戻す。既存の単発SFXは自然に終了させる。操作説明とタイトル／結果画面の案内を同じ変更で更新する。

音声遷移は新規出撃の共通処理にまとめる。TitleからPlayへ入る際は`music_stop()`と`set_engine(0)`を呼び、初期化後の速度90m/sに対応するエンジン音を開始する。GameOverからPlayへも同じくBGMを停止する。PauseからPlayへは出撃状態を初期化せず、現在速度のエンジン音へ復帰する。Titleへ戻る時はタイトル用BGM、GameOverへ入る時は専用の下降系BGMをループ再生する。直接リトライを3回繰り返しても戦闘中に結果画面のBGMが残らず、Pause復帰で速度と音が対応することを実機で確認する。

目標案内の初期仕様は「ロック対象を優先し、それがなければ最寄りの生存敵を選び、その敵が生存する間は維持」とする。案内対象はロック判定と別のIDで持ち、画面外に出ても消さない。自動選択だけとし、目標切替キーは増やさない。真後ろは右旋回を案内し、上下差は上下の記号で併記する。画面端の内側8pxに矢印を収め、表示領域内へ戻れば消す。`Proj::ok`は画面外の余白も含むため、160×160の実表示範囲で判断する。

完了条件: 初見の人が説明書なしで開始・ロック・発射・再出撃できる。固定した導入シナリオでは30秒以内に敵を発見できることを目標にする。ポーズ復帰で勝手に発射せず、結果画面の数字が変化しない。デモは通常プレイと同じ更新・描画経路を通り、表示上のHUD・警告・ロック・攻撃・撃墜が実プレイと一致する。実機で複数回試し、見失う時間と初撃墜までの時間を旧版と比較する。

初見評価は任意のユーザビリティ確認であり、v1.0.0の公開必須条件ではない。実施する場合は、説明書を隠すのではなく、READMEの操作説明を含む通常の配布条件で、シード`0x12345678`・初期条件を固定して記録する。開始・敵発見・ロック・発射・再出撃でつまずいた箇所を改善材料として残し、少人数の結果を一般的な成功率とは扱わない。旧版との比較を行う場合は、習熟後の参考記録として初見評価と分ける。

### Phase 2: 短いミッションと達成感を加える

Phase 1の操作感を確認してから着手する。大きなストーリーやショップは導入せず、既存敵の編成を使って3つのミッションを作る。

| ミッション案 | 内容 | 成功・失敗 |
|---|---|---|
| FIRST SORTIE | Fighter 2機。前方出現、弱めの攻撃で基本操作を覚える | 全撃墜で成功、自機HPゼロで失敗 |
| BOMBER HUNT | Bomber 1機とFighter 2機。撃破の優先順位を選ぶ | 制限時間内のBomber撃墜で成功、時間切れまたは自機HPゼロで失敗 |
| ACE ENGAGEMENT | Fighter中心の編成からInterceptor混成へ、全2Wave | 全Wave完了で成功、自機HPゼロで失敗 |

- タイトルでMission / Endlessを選択し、出撃前に目標を1画面で提示する。
- 同時敵数5の上限内で構成し、補給量・制限時間・編成を定数テーブルにする。難易度は初期1種類で調整する。
- ミッション結果に時間・残HPを加味したランクを付け、計算式を文書化する。同一フレームで目標撃破と自機撃墜が起きた場合は失敗を優先する。
- `mission.*`等を追加する場合は、目標判定と編成データに責務を限定する。全体の大規模な書き直しを前提にしない。

完了条件: 3ミッションで成功・時間切れ・自機撃墜・再挑戦の経路を確認できる。各ミッションの狙いが操作と編成から感じられ、目標の3〜5分に収まるか実測して調整する。Endlessも従来どおり進行できる。

### Phase 3: 見た目・音・記録を仕上げる

- 敵種を色だけでなく機影でも区別する。機銃命中、撃墜、ミサイル航跡を既存の描画プリミティブで磨く。
- ミッション別の空・地面の配色と少数の遠景を追加する。照準周辺の視認性を優先する。
- Phase 1で追加した二段階警告音の音圧・識別性・スピーカー再生を実機で確認し、ロック音・ミサイル音・爆発音との優先度を必要に応じて調整する。戦闘BGMは導入せず、タイトル曲を使うデモでは引き続き戦闘SFXを抑制する。
- ハイスコアのSD保存はv0.9.13で実装済み。保存はゲームオーバー確定時だけに限定し、
  `SKYHI_A.DAT`／`SKYHI_B.DAT`のチェックサム付き2スロットで既存記録を保護する。
  SDなし・マウント失敗・書き込み失敗でもセッション内の記録を保持し、ゲームを止めない。
  クリア記録やミッション別ランキングは別機能として扱う。

完了条件: 敵種を機影でも識別でき、連射中も警告が聞き取れる。SDなし・書込失敗でも次のプレイへ進める。性能基準を満たさない装飾は縮小する。

## 4. 守る技術条件

- `lcd_rgb565_pio.cpp`、`lcd_rgb565_pio.h`、`lcd_spi_min.pio`は変更しない。[LCD調査履歴](LCD_BRINGUP_HISTORY.md)に従い、描画変更はゲーム層、必要なら`picocalc_display.cpp`で扱う。
- RP2040の標準構成、160×160のRGB565、2倍表示を維持する。高解像度化、PSRAM必須化、Pico 2専用化は本計画の対象外。
- 通常戦闘の更新＋描画＋転送が95パーセンタイルで33ms以内を暫定目標にする。基準版が超える場合は先に原因を調べ、達成済みと扱わない。F5の同期保存時間は別枠で記録する。
- フレーム単位の移動・タイマーを維持する間は、処理落ちでゲーム速度が変わる点も検証する。可変時間刻みやマルチコア化は必要性が計測で示されてから判断する。
- 新しい毎フレームの動的メモリ確保は避け、配列・演出数に上限を設ける。RAM使用量、スタック余裕、Flash増加量を各段階で比較する。
- F5保存は同期処理のままとし、遅いSDやSDなしでの復帰、3秒ウォッチドッグとの関係を確認する。保存の非同期化は別途必要性を判断する。
- 実機USB操作を行う際は上位`AGENTS.md`指定のWindows PowerShell版`workspace-management/PicoCalc-Hardware.ps1`を使用する。

## 5. 検証とリリース

| 検証 | 合格条件 |
|---|---|
| ビルド | CMake/NinjaでUF2を生成でき、新規警告がない。既存FatFsの限定抑制を拡大しない |
| ロジック | 状態遷移、結果固定、標的スロット再利用、ミッション成功と失敗を小さい再現テストで確認する |
| 操作 | 旋回＋機銃＋ミサイルの同時操作、長押し、ポーズ、再出撃で入力が残らない |
| 戦闘 | 画面内外の目標、ロック喪失、弾切れ、衝突、最終敵撃破と自機撃墜の同時発生を確認する |
| 性能・安定性 | 上限負荷でフレーム時間を測り、20分連続プレイで表示崩れ・フリーズ・予期しない再起動がない |
| 起動・保存 | コールドブートと通常起動、SDなし／あり、F5成功／失敗からの復帰を確認する |
| 体験 | 初見プレイの操作迷い、接敵時間、初撃墜時間、敗因の理解を記録し、Phase 1の前後で比較する |

実装着手時に必要なロジックだけをハードウェア依存から分けてテストする。現状のCMakeにはテストターゲットがなく、ホストテスト基盤は未整備。実機でしか確認できないLCD・音・同時キー入力は、ホストテストの合格で代替しない。

各Phaseを独立してレビュー可能な単位にする。Phase 0〜1を最初のアップデート候補とし、その評価後にPhase 2を進める。挙動変更を含む配布では`VERSION`を更新し、UF2、変更履歴、操作説明、比較画像、検証結果を揃える。今回のデモ経路・主旋律・バージョン表示の再調整では`VERSION`を0.9.3へ更新する。

## 6. 作業量の目安と最初の着手点

1人で実装し、実機を使える場合の概算。日数は作業日で、環境構築や実機の利用待ちは含めない。

| 段階 | 概算 | 依存 |
|---|---|---|
| Phase 0 | 3〜5日 | 実機・ビルド環境、現行版の比較記録 |
| Phase 1 | 3〜5日 | Phase 0の挙動確認と性能基準 |
| Phase 2 | 4〜6日 | Phase 1の操作感の評価 |
| Phase 3 | 3〜5日 | Phase 2の内容確定、残りの性能予算 |

Phase 0は「基準取得: 0.5〜1日」「再現・計測基盤と4件の修正、ホストテスト: 2〜3日」「実機比較と記録: 0.5〜1日」に分ける。基準取得後に残作業を見積もり直す。

全体13〜21作業日を初期目安とする。実機や初見評価の協力者を待つ時間は含めない。実機評価で難易度や視認性の調整が必要なら、後続の装飾・保存機能より優先する。

最初の実装は「基準版の保存と再現・計測基盤 → 開始時状態・結果確定・標的寿命・照準投影の修正 → Phase 0の検証 → ポーズと直接リトライ → ロック進行と命中表示 → 目標案内 → 敵射撃の予告」の順とする。Phase 1までを最初の公開範囲とし、ミッション編成・制限時間・ランク式の具体値はPhase 2着手時、保存形式はPhase 3着手時に確定する。後続Phaseの調整値をPhase 0開始の前提条件にはしない。
